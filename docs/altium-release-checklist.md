# Altium release checklist (manual, AD26)

CI cannot run Altium Designer, so the DelphiScript units ecadlib installs into Altium are only checked as text
there (`tests/test_altium_menu.py`, `tests/test_altium_native.py`, `tests/test_altium_scripts.py`: balanced
Begin/End, no forward calls, no Altium call outside the documented list). Before every release, one person runs
this list on a Windows PC with Altium Designer 26 and a licence. It takes about 20 minutes.

The units are real files in [`ecadlib/altium_scripts/`](../ecadlib/altium_scripts):

| File | What it is |
|---|---|
| `ecadlib_menu.pas` | the **ecadlib** menu entries (Add part from MPN, Check project BOM, Open review queue) |
| `ecadlib_dialog.pas` | the dark ecadlib dialog the entries open (with `ecadlib_dialog.dfm`, generated by `altium_forms.py`) |
| `ecadlib_build.pas` | BuildLibraries: Altium writes the .PcbLib / .SchLib files itself |

`@VERSION@` in their header comment is the only thing filled in when ecadlib writes them. If you edit a unit, run
`python -m tests.run_all test_altium` before you push, then this whole list.

## Before you start

- [ ] Install the release candidate: the `ecadlib-setup-X.Y.Z.exe` from the release workflow, or
      `pip install ecadlib==X.Y.Z`. `ecadlib --version` prints the new version.
- [ ] Use a folder path with no spaces and no accented letters (`C:\ecadlib-test\X.Y.Z`). A script path with them
      makes Altium start a second, unlicensed copy.
- [ ] Close Altium. Make sure Altium is licensed when it starts. An Altium started by a script without a licence
      crashes every native build until you restart it.

## 1. Install the menu

- [ ] Setup page **Add to Altium** (or `ecadlib altium-menu build` then `ecadlib altium-menu install-menu`).
- [ ] Start Altium and open a schematic. The **ecadlib** menu is in the menu bar, with the entries above.
- [ ] Open `Documents\ecadlib\altium-menu\ecadlib_menu.pas` in a text editor. Its header names the new version.

## 2. Add part from MPN

- [ ] **ecadlib > Add part from MPN...**, type `LM358DR`. The dialog opens dark, the progress rows fill in, and it
      ends with the part in your library (or Altium 365 when `ecadlib.toml` names a workspace).
- [ ] The dialog can be dragged by its header, and **Close** while it works asks before it stops waiting.
- [ ] Try an MPN that needs the AI datasheet read. The dialog shows the cost and waits for your click. Say no:
      nothing is sent.
- [ ] Try an MPN no source has. The dialog says why the part is held and what to do.

## 3. Check project BOM

- [ ] Open a project and run **ecadlib > Check project BOM**. The report opens and offers to fill the library.
- [ ] Fill it. The parts that are ready go in. Held parts are listed with the reason.

## 4. Native build (ecadlib_build.pas)

- [ ] After a fill or Reinstall, Altium writes the .PcbLib / .SchLib itself (`native_build=1` in
      `ecadlib_menu.ini`). `ecadlib_build_report.txt` lists every library as built, with no `failed` line.
- [ ] Place one generated part. The footprint has `.Designator` on the assembly layer. The symbol follows the
      house style: inputs on the left, outputs on the right, power at the top, ground at the bottom. Resistors use
      the US zigzag symbol, and two-pin passives hide their pin names and numbers.
- [ ] A part with De Morgan display modes switches modes in the schematic.

## 5. Review queue

- [ ] **ecadlib > Open review queue** opens the web UI at the queue, and starts it when it is not running.

## 6. Clean up

- [ ] Close any crash or error dialogs your own test runs left open. Don't close other people's documents.
- [ ] Write the result in the release notes: "AD26 checklist passed on <date>", or the step that failed.

If a step fails, don't release. File an issue with the step, `ecadlib_build_report.txt`, and the job folder
(`Documents\ecadlib\altium-menu\jobs\<id>\`, with `request.ini`, `result.ini` and `progress.ini`).
