# Changelog

All notable changes to ecadlib are recorded here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the
project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Until 1.0.0,
a minor release may change command-line options and file formats.

## [Unreleased]

### Added

- Change control (#105): no library update can silently change a released part. Every writer (librarian re-runs, `upstream --update`, `upkeep --apply`, resolve, dedupe, datasheet passes, style apply and the KiCad / DbLib / Altium 365 publishers) compares what it would leave with the released revision, classifies each difference (identity, electrical, geometry-major, geometry-minor, cosmetic) in plain words, and holds what the `[change]` policy says to hold until a person approves it (`approvers = 2` is the two-person rule). New: `ecadlib part status|show|diff|history|approve|reject|revert|fingerprint`, the append-only `library.ledger.jsonl` with every released file kept for revert, the held update and the revisions in the web UI, an approved change pushed as a new Altium 365 component revision (optional life-cycle transition `[change] a365_transition`), `ecadlib project check|freeze|scan` (KiCad drift and freeze, the Altium 365 out-of-date list, the usage index), and an upkeep `changes` check. Corpus run over KiCad 9.0.8 to 10.0.0: 234 parts held, all real changes, none missed (docs/change-control.md).
- The datasheet reader asks for the maker's thermal-pad land (`land.ep_across` / `land.ep_along`, e.g. TI PowerPAD's 3.4 x 5 mm around a 3 x 3 mm exposed pad), and the footprint's exposed pad uses it, as KiCad does. The reader's schema changed, so answers saved before are read again on the next live run; `ecadlib eval run --cached-only` still scores them (sync and batch runs).
- Fixes from the first live benchmark runs (#42). A dimension printed with its tolerance (6.5±0.2, 3.56 +0.15/-0.25) or as a range (6.3~6.7) gives min and max instead of being left blank (LP38693MP-1.8). A blank pin count is taken from the package name or the pin table when they agree, never from a depopulated name like SOIC-14-16 (UCC25800). A read whose optional-fields text is filler ("x") is no longer thrown away, and a part's route keeps its best answer when a later read comes back worse (CY14U256LA-BA). A fine-pitch BGA land read as SMD-defined whose copper would not fit the pitch is built copper-defined with a note (TPS628436YKA). The kicad-v1 errata gain PCA9557BS (KiCad's reference is the 3 x 3 mm variant; the BS part is SOT629-1, 4 x 4 mm at 0.65 mm) and 27C256 (pins O0-O7 as the datasheet names them, and its real DIP-28 body).
- `[datasheet] max_cost_usd` gives back the worst case it held for a request the API answered with an error, or a batch request that errored, expired or was cancelled: none of them is billed. In the #42 Sonnet 5.5 run those holds stayed on the books and the cap refused 34 parts at $6.21 of real spend. A timeout keeps its hold, since the API may still have run it.
- `ecadlib eval run` no longer charges a live run with the estimate of a part that got no answer (a download the API's fetcher gave up on, or a rejected read): it cost nothing, and the report said so with a made-up price (the first Opus 5.5 run showed $32.41 against $16.00 really spent). A datasheet the API's fetcher timed out on or could not connect to counts as no PDF, like one it could not download.
- The live accuracy harness (#42): `ecadlib eval run` records each part's datasheet (URL, SHA-256, pages sent) and the reader's prompt version, gives every failed part a failure type (no PDF, blank dimension, cross-check hold, wrong unit, wrong variant, mirrored, misread table, thermal pad, misread dimension, maker land, symbol) and reports the pad match over the footprints built. `ecadlib eval pin REPORT` pins the PDFs a run read (`<set>.pins.json`; `eval run --pins`), so a later run flags a datasheet the maker changed. `ecadlib eval publish REPORT` writes the results page: one headline (model, parts, pass rate, pad match, cost per part, failures by type), then every miss. The **Accuracy benchmark (live)** GitHub workflow runs it on demand with a cost cap (no schedule; needs the `ANTHROPIC_API_KEY` secret).
- docs/benchmark.md: the live accuracy benchmark on 110 real parts (#42), with the method, results per family, every miss and its cause, the cost and the commands to run it again; the website shows the headline numbers.
- `ecadlib eval run` tells a footprint that uses the datasheet's recommended land pattern (the maker's example board layout) apart from a misread: when it misses KiCad's pads only because KiCad works its land out from the package dimensions, the report says so and gives the pass rate counting those as right (`summary.maker_land`, per case `maker_land` and `kicad_differs_maker_land`). Checked by hand on CD4066BM, UCC256301 and BCR430UW6.
- A test set can carry an errata file (`<set>.errata.json`) of cases where KiCad's reference disagrees with the datasheet, checked by hand: the field is scored right when ours is what the datasheet says, and the report lists it. kicad-v1 has one: AH1806-W, whose SC59 pins 2 and 3 KiCad swaps.
- The standard source knows DO-201AD (axial, 15.24 mm bend), MicroMELF and SC-82AB, from KiCad's hand-drawn footprints (618 packages, each benched against KiCad). Three #42 benchmark parts (1N5400, BAV301, NCP662) now build without a datasheet.
- `ecadlib eval run --cached-only` re-scores a live run's out folder with nothing sent: its cached answers, and the answers of its collected batches downloaded again (free), are read by the current code; a part that would need another read is reported, not sent.
- `ecadlib eval run --batch` sends the datasheet reads as one Message Batch (half price); the report prices those parts at the batch rate, and recordings keep it so a replay gives the same cost.
- `ecadlib status` shows how long the last BOM run took, step by step: triage, build, release check, review (from the release check to the last sign-off, `--allow` or resolve choice) and the Altium 365 push, with ecadlib's own time and the total (#44). Each plan folder keeps a `timing.jsonl`; `status --json` has `last_run` and a `timing` per plan.
- `ecadlib status` shows the review rate: of the parts built, how many passed first time, are held (with the top reasons), were approved, rejected or changed by a person (#45). `status --json` has `review`, overall and per plan.
- docs/START_HERE.md asks people trying ecadlib to send those two lines.
- `ecadlib eval run` reports the parts that never reached the model (no datasheet PDF could be fetched) apart, with the pass rate without them (`summary.no_datasheet`, `summary.with_datasheet`).
- A logo: the Sprout Trace mark (a copper trace growing from a via into two leaves) on the website, its favicon, the web UI, the KiCad toolbar button and the Windows icon, with copper as the one accent colour. docs/brand.md has the rules; `site/brand/` has the files.

- The Altium dialog, the KiCad window and the web UI show the model and the cost of every AI step before it starts, and wait for a click: Fill the library and Add part run every free source, then price the datasheet reads a part still needs ("3 parts need the datasheet read by AI (claude-opus-5-5): about $0.42, at most $1.10"). Above `[datasheet] ask_above_usd` (new, default $1.00) or `max_cost_usd` they ask a second time. The reads are held to the amount approved, and the real cost (from the API's usage) is shown next to the estimate afterwards (#49). The house style guide is priced the same way. `Workspace.ai_quote` / `ai_read`, `/api/ai/quote`, `/api/ai/read`, `/api/style/guide`; `ecadlib/ai_cost.py`.
- `ecadlib doctor` warns when a paid AI key comes only from an environment variable, which other programs can read and bill.
- docs/api-keys.md: where your key lives, who can read it, and how the cost is shown.
- `ecadlib mcp --http`: the MCP server over Streamable HTTP for agents that cannot start a local program, such as Grok through the xAI API. A bearer token is required (`--token` / `ECADLIB_MCP_TOKEN`, else one is printed), web page origins are refused, and file arguments must stay inside the workspace and `--lib` folders.
- `ecadlib mcp --tools core|read-only|<names>` (or `ECADLIB_MCP_TOOLS`) offers fewer tools, for small models and remote agents.
- MCP tools `upload_bom`, `ai_quote`, `ai_read`, `house_style_guide` and `job_status`; every tool has a title and read-only / destructive / internet hints; the server sends usage instructions on connect.
- docs/mcp.md: setup for Claude Code, Claude Desktop, Codex and Grok.
- docs/START_HERE.md walks an Altium user from the installer to a project BOM released into Altium 365, all from the ecadlib menu: the Nexar token and workspace, Check this project BOM, Fill the library with the AI cost shown first, the review queue for held parts, and the Components panel (#51).

### Removed

- To keep one maintainer on the BOM-to-Altium 365 flow, about 7,000 lines are gone from `main` (the last code with all of them is the `archive/before-trim` branch; `pip install "git+https://github.com/oliBrowne/PCBLIVINGLIBRARY@archive/before-trim"`): the JLCPCB assembly check and BOM / CPL export (`ecadlib assembly`, #104 is now out of scope), the SPICE / IBIS model finder (`ecadlib sim-models`), the price, stock and alternates report (`ecadlib sourcing` and upkeep's `sourcing` check; Nexar, DigiKey and Mouser still identify parts), the library hub (`ecadlib hub`), and the team server with sign-in, roles, Docker and HTTPS (`ecadlib team`, `ui --team`, the compose files). The library agent (`ecadlib agent`, `agent-watch`, `queue`) and two-way Altium 365 sync (`ecadlib a365` pull / status / reconcile; `ecadlib altium365 push` stays) are parked on the `parked/agent-and-a365-pull` branch. The KiCad plugin manager package is frozen: it still builds but gets no new features. The removed commands say where the code went; an `ecadlib.toml` with `[sim]`, `[hub]`, `[assembly]`, the old `[agent]` keys or the upkeep price keys still loads and those keys are ignored, as is `notify` `batch_ready` / `part_held`.
- The Fusion Electronics / EAGLE (`ecadlib eagle-export`, `.lbr`) and EasyEDA Pro (`ecadlib easyeda-export`, `.elibz`) exports, with their web UI buttons, `POST /api/export/tool`, the Workspace and MCP `tool_export`, the Fusion and EasyEDA columns of the library hub, the `fusion/` and `easyeda/` folders of `ecadlib testpack` and the `[release] eagle` / `easyeda` checks (#50). Why: no user asked for them, neither was ever opened in the real tool, and about 3,000 lines of writers and read-back took one maintainer's time away from the BOM-to-Altium 365 flow. The two commands now print that the last version with them is 0.3.1 (`pip install "ecadlib==0.3.1"`); an `ecadlib.toml` that still sets `[release] eagle` or `easyeda` loads, and the keys are ignored. Importing parts *from* EasyEDA / JLCPCB is unchanged.

### Changed

- EasyEDA / LCSC and the JLCPCB search (undocumented endpoints) are off by default: `[providers] unofficial = false`. `ecadlib init` asks whether to use them; set `unofficial = true` to opt in.
- `[datasheet] max_cost_usd` defaults to $10 per run (0 = no cap), so a scripted run on a big BOM has a ceiling. `--yes` no longer lifts the cap; `--max-cost-usd N` on `ecadlib datasheet` and `ecadlib eval run` changes it for one run. The dialogs still ask twice above `ask_above_usd` (or a cap you set).
- `ecadlib eval run` without an API key reports the parts that needed the AI read as "not run: no API key", not as wrong, and prices them as an estimate.
- When a setting fails to load and ecadlib falls back to a default (a model setting, a house-style parameter name, a model's guide rails), it prints a warning and review.md / review.html lead with it, instead of carrying on silently.
- The Altium DelphiScript units (`ecadlib_menu.pas`, `ecadlib_dialog.pas`, `ecadlib_build.pas`) are real files in `ecadlib/altium_scripts/`, no longer Python strings; what ecadlib writes into Altium is byte-for-byte the same. docs/altium-release-checklist.md is the manual AD26 pass for every release.
- API keys are read from ecadlib's own key store when they are needed and are never copied into the environment (they used to be copied into each ecadlib process's environment, which every program it started inherited). A stored key now comes before an environment variable of the same name; the variable is used only when nothing is stored. The Altium menu README no longer suggests `setx`. The eval gate and golden builds never read the key store.
- pypdf is a core dependency (it was the `[pdf]` extra): without it a large datasheet (the 1976-page SAM E70 family sheet) could not be cut to the pages that matter and every read of it failed.
- MCP: a missing or wrong argument is now a tool error the model can read (it was a protocol error), naming the arguments the tool takes; `null` optional arguments, numbers and booleans sent as text and objects sent as JSON strings are accepted. `librarian_run`'s `refresh` takes a list of part names and `refresh_all` redoes everything (`refresh: true` still works). Answers are compact JSON without `\u` escapes and are cut at `--max-chars` (default 80,000) with a hint.
- Datasheet downloads are more reliable. A PDF download that times out, loses its connection (reset included), or gets 429 or a 5xx is tried twice more with backoff, honouring Retry-After up to 30 s; a TLS or proxy refusal is not retried, and later links on a host that failed every try get one try each in that run. After every BOM, part-search and source link, the maker's own URL pattern is tried for Texas Instruments (`ti.com/lit/ds/symlink/<part>.pdf`) and Analog Devices / Linear (`analog.com/.../data-sheets/<part>.pdf`), full part number first, then the base part (LT8610EMSE#PBF -> lt8610, TPS26630PWPR -> tps26630). When a maker's site refuses the download (403 with a web page, a reset connection, a timeout on every try) and the API cannot fetch it either, the held part says so and how to get round it: download the PDF in a browser and read it with `ecadlib datasheet FILE.pdf --part MPN`. The User-Agent is unchanged; PDF requests ask for `Accept: application/pdf,*/*;q=0.8`.

### Fixed

- Fixes from testing PRs #81-#103 by running them (tests in `tests/test_review_1018_merges.py`):
  - A failed Altium build installs the library you had again (it was uninstalled to build); the dialog says "Not found" for a bad part number, and a wrong LCSC number is no longer reported as a bad MPN.
  - `dblib-sync`: a library file open in Altium is reported by name and skipped, instead of stopping halfway with "[Errno 13] Permission denied".
  - ICs "with integrated MOSFETs" stay in the ICs table, not Transistors.
  - Footprint hashes recorded before #97 are computed again (librarian_state v3, `ecadlib migrate`), so a re-run shares a footprint the library already has instead of writing a second copy.
  - Altium 365 push: a part is matched by its exact name or a revision of it, never a colleague's part whose name only starts the same (LM358 vs LM358-N).
  - `ecadlib status`: a push that failed is not shown as released, an interrupted run does not hide the last finished one, and the total time is never negative.
  - A NOTICE.txt you wrote yourself is never overwritten.
  - MCP: `save_rules` cannot change where model requests (and the stored API key) go; the first calls to an HTTP server share one job list, so the one-writer-per-BOM lock holds; a "still running" job stays readable for the caller it was named to; `altium_menu` takes a Windows `win_dir` under `--confine`.
  - Benchmark scoring: an erratum no longer hides wrong pins it does not list; a "maker's land" narrower than the leads read from the same drawing is not counted as the maker's; pad-table bodies turn by the direction the pin rows run (SOT-223, DIP-6, DIP-8).
  - `fp-edit` reads a part's latest spec, and a datasheet read whose `other_json` comes back as an object is accepted.

- A gull-wing exposed pad read long side first (TLC5951DAP's PowerPAD, 5.7 x 3.04 mm) is turned to run with the body; across the rows it pushed every pad's heel out past the body.
- A DIP or other pad table with its rows down the page now gets a body (and courtyard) that runs with the rows: 27C256's courtyard was 37 mm wide.
- Two parts whose datasheet packages share a name but not their numbers (ISL8117FVEZ and TPS26600PWP, both HTSSOP-16) keep their own spec file; `ecadlib fp-edit` reads each part's own.
- `ecadlib eval` pin names: "N.C." is KiCad's "NC".
- `eval run --cached-only` scores a part from its best saved answer for the same datasheet when the route now asks for a step the live run never sent (it went another way past an answer the old parser rejected).
- A BGA body read the other way round from its ball grid (CY14U256LA-BA: 8 x 6 balls, body 10 x 6 mm) is turned so its long side runs with the grid's long side, with a note.
- Benchmark scoring: a pin name spelled out ("Enable", "Ground") counts as KiCad's "EN" / "GND"; the eval BOM names through-hole diodes D, as a real BOM does, so DO-41 / DO-201AD parts resolve from the standard table.
- Datasheet answers whose `other_json` objects left out optional fields (a land without `pad_center_y`, a tab given as bare numbers, a number as text) were rejected as "not valid under any of the given schemas"; they are now read (missing optional fields become null, a bare number for a range is its nominal). The #42 benchmark lost 23 paid answers to this.
- A batch answer the parser rejected is downloaded again from its collected batch (free, within the API's 29 days) and read by the current code, instead of being bought again on the next run.
- The pin-1 triangle of a tiny QFN (QFN-16 1.8x2.6 mm) moves out past the top-row pads instead of sitting 0.07 mm from pad 16 (KLC F5.1).
- `[datasheet] max_cost_usd` counts each answer at what it really cost once it comes back, not at its worst-case estimate. A multi-round run (more pages, a stronger model) was refused its second round long before real spend reached the cap: the #42 benchmark's first round was held at $24.61 and cost $3.42.
- Converted footprints were all labelled "(CC-BY-SA 4.0)" in their description, including EasyEDA parts, your own `--lib` files and footprints ecadlib generated; only parts from the KiCad libraries are labelled now (#54).
- A part whose symbol or footprint comes from the KiCad libraries now gets a `Library Credit` parameter on the Altium side, as EasyEDA parts already did, and the librarian writes a `NOTICE.txt` in its output folder naming the third-party terms of the parts in it (#54).
- MCP `librarian_run` ran the paid datasheet reader without a price or a yes. It now prices those parts (`ai`) like the other front ends, and `ai_read` needs the approved amount. `learn_house_style` with `ai` returns a quote too.
- MCP calls that take longer than `--wait` (default 45 s) answer with a job id for `job_status` instead of running into the client's timeout (Codex waits 60 s).
- MCP: a child process (kicad-cli, pdftoppm, git) can no longer write into the protocol stream on stdout.
- The Altium menu and the web UI no longer tell you to put NEXAR_TOKEN in an environment variable and restart: the token is read from ecadlib's key store (setup page, Optional keys).
- Datasheet page picking: a family sheet's "LQFP144, 144-lead LQFP" no longer counts as this part's LQFP-100 (a bare family word matched every LQFP), and the drawing and land-pattern slots never go to a page about another package. The SAM E70 sheet (1976 pages) now sends the LQFP100 drawing instead of the LQFP144 and QFN pages.
- Standard parts: DO-41 (DO-204AL, SOD81) on a diode resolves to KiCad's D_DO-41_SOD81_P10.16mm_Horizontal.
- Datasheet checks: 1.25 mm (JST GH) is a standard pitch.
- Datasheet reader: an answer whose `other_json` the model fenced or wrapped in a sentence is read instead of rejected.
- Datasheet download: a plain http:// link that fails here is tried again over https before it is sent to the API.
- BGA / WCSP footprints: a ball grid that fits the body only turned a quarter turn (the datasheet's length x width on the other axis than its rows x columns, TPS628436YKA) turns the body and says so in the report, instead of refusing the read.
- A datasheet read that leaves a needed dimension blank without listing it as unresolved says which one.
- Datasheet download: a link that gives a product HTML page (ENS210) is followed once to the datasheet PDF the page links to; the provenance keeps the page as `page_url`.
- Datasheet reader: a plain http:// datasheet link sent to the API for it to fetch is sent as https:// (the API answered "Only HTTPS URLs are supported"; 7 parts of the live benchmark).
- Cross-check: two reads that name a pin with different wording agree: "K" and "cathode (K)", "A" and "anode", "VO" and "VO (output)", "V_{SS}" and "VSS", or "GND" and "PowerPAD" for the exposed pad. 18 benchmark parts were held on wording like this.
- Datasheet reader: the live API refused every read ("Schemas contains too many parameters with union types (184 ...). limit: 16"). The request now asks for the dimensions as a list of named records (min / nom / max as printed text, "" where blank) and the optional family fields as one JSON text, with no nullable fields; the answer is turned back into the same extraction as before, so checks, the result cache and recorded answers are unchanged. The cross-check's second read had the same problem (26 union fields) and is fixed the same way.
- Datasheet reader: the optional family fields reached the model without their descriptions, so a land pattern's `pad_center` came back as the datasheet's C (row to row) and SOT-23-6 pads sat 2.4 mm out instead of 1.2 (BCR430UW6, AH1806-W). The descriptions are back, `pad_center` says C / 2, and a pad_center past the leads is flagged.
- `ecadlib eval`: KiCad's pin-name markup (`V_{SS}`) matches the datasheet's plain `VSS`.
- Datasheet reader: an answer with no `unresolved` list crashed ("'NoneType' object is not iterable"), and a read that left a needed dimension blank crashed the footprint build (`KeyError: 'terminal_length'`, "'>' not supported between NoneType"). The part is now left for review with "no footprint: the datasheet read left terminal_length unresolved". A bug in a source names its file and line in the part's log.
- Datasheet reader: a maker's link that refuses this machine (HTTP 401, 403 or 429: Nexperia, Renesas, Altera on the live benchmark) is sent as a URL for the API to fetch, as a blocked host already was; only a 404-style error, an HTML page or an oversized file rules a link out.

- Altium 365 push: symbols and footprints are released under the `[folders] root` too (`<root>/Models/Symbols`, `<root>/Models/Footprints`), not always under `Components/Models`, so a test root keeps everything together.
- Altium 365: Nexar renamed `DesRevision.id` to `revisionId`; push, `a365 pull/status` and `upstream check-a365` asked for the old field and every lookup failed with HTTP 400. The test schema is updated to match.
- Altium 365 push: a nested component folder (`ecadlib-test-47/ICs`) is released under its parent folder's id; Nexar takes only one folder name there and refused the path ("AddALU_FoldersInvalid folder HRID"). Missing parent folders are created (`desCreateFolder` with the live `parentFolderId` / `folderId` fields).
- Altium 365 push: a symbol or footprint several parts share (Capacitor, C_0603) is released with the first part and linked by the others; releasing it again failed with "AddALU_ItemsDuplicate item HRID". A symbol or footprint item named like its component gets `-SYM` / `-FP` (Altium 365 refused "Duplicate ID").
- Altium 365: looking a component up by name matched other items too (Altium's sample part `CMP-017-000002-1` for `AMS1117-3.3`), so a push or lifecycle update could change a part that is not ours. Only an item of that name (or its revision) counts now.

## [0.3.1] - 2026-10-17

### Added

- Altium builds the libraries itself (`ecadlib/altium_native.py`, docs/altium-native.md): every `.PcbLib` / `.SchLib` ecadlib writes gets a `.ecadbuild` recipe, and a DelphiScript (`ecadlib_build.pas`) rebuilds them inside Altium with its own object API; `ecadlib altium-native write|compare` and a *Rebuild with Altium* step in `altium-pkg` (`--no-native-build` to skip). `compare` reads Altium's result back pad by pad and pin by pin.
- The ecadlib menu in Altium lets Altium build the library files itself before it reinstalls the library: each job copies the parts' build recipes into the library folder and writes `ecadlib_build.txt`, and the menu calls `BuildLibraries` (`ecadlib_build.pas`, now part of the menu's script project). The dialog says when a library failed to build. `native_build=0` in `ecadlib_menu.ini` turns it off.
- Altium footprints carry the designator on the assembly drawing too: KiCad's `${REFERENCE}` on F.Fab becomes a `.Designator` on Mechanical 13 (the `[layers] assembly` layer), and footprints without one get it centred on the body. `ecadlib parity` and the footprint check compare it between KiCad and Altium (#37).
- Edits made in Altium are kept: each library ecadlib copies into a library folder gets a `.ecadstate` (the hash of ecadlib's file and of the file Altium built from it). A library someone changed in Altium afterwards is no longer rebuilt by the native build or replaced by `dblib-sync` / `altium-pkg`; they report it instead (`dblib-sync --overwrite-edits`, `altium-native write --rebuild-all` replace it). Libraries Altium already built and ecadlib has not changed are not rebuilt on every run.
- `ecadlib fp-edit PLAN --part P show|rename OLD=NEW|same-net A,B|undo`: fix a held part's datasheet pad table by hand, e.g. a connector whose pads are named 1+ / 1- or T / R / S (a footprint still needs a pad 1 or A1, so a person picks it). The edit is kept in `footprint_edits.json` next to the plan, applied whenever the librarian builds the part, and noted on the part with who made it. A part held because its datasheet pad table failed the check now says which check failed and what to do (no pad 1: rename a pad with `fp-edit`; pads of two nets overlap: `same-net` if they are one net, else pick a footprint), instead of "there is no footprint yet".
- `ecadlib sources-check` and a weekly `sources-canary` workflow: checks the unofficial EasyEDA / JLCPCB endpoints against known parts.

### Changed

- Pads on one net may overlap in a datasheet pad table: pads whose pins share a name in the pin table (VIN on pins 1, 2 and the paddle) are put in `same_net` automatically (NC / DNC pins never are). An exposed pad listed twice at the same place with another size (for its thermal vias) is one pad, not a misread; an exact copy is still an error. The accuracy gate's baseline moves to 328/331 (qfn-DAC60504).
- Official part APIs first: the default provider order is Nexar, DigiKey, Mouser, then the unofficial JLCPCB search and EasyEDA. Nexar / DigiKey / Mouser answers now give the LCSC number and datasheet link. `[providers] unofficial = false` turns the unofficial endpoints off completely.

- Altium (Altium 365 first) and KiCad are the supported targets. The Fusion Electronics / EAGLE and EasyEDA Pro exports are marked experimental in the README and `ecadlib -h`: they keep working but get no new features and may be removed later.

### Fixed

- BOM intake: `C1~C4` designator ranges are counted; European decimal quantities are not multiplied by ten; one cp1252 byte no longer garbles a UTF-8 CSV; `DNP` / `DNF` in the Value or MPN cell marks the line; a quantity-only footer row is not a part; an MPN that Excel turned into scientific notation is flagged.
- DbLib table: parts go to the right table (LCSC long descriptions, `easyeda:C7593` is an LCSC number, an IC package outranks the description words, menu parts follow their source).
