# Changelog

All notable changes to ecadlib are recorded here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the
project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Until 1.0.0,
a minor release may change command-line options and file formats.

## [Unreleased]

### Added

- Your library across tools (`ecadlib/hub.py`): a **Your library** page in the web UI (shortcut `l`), `ecadlib hub`, Workspace `hub` / `hub_part` / `hub_fix` / `hub_build_bom`, `GET /api/hub`, `GET /api/hub/part`, `POST /api/hub/fix` (librarian), MCP `library_hub` / `library_hub_part`. Every part once, from your libraries (`--lib` and `[hub] libraries`: .SchLib, .PcbLib, .DbLib, .kicad_sym, .pretty, .kicad_dbl, Altium 365 lists) and ecadlib's plans, with a cell per tool (Altium, Altium 365, KiCad, Fusion, EasyEDA): missing, same, different or behind, compared on pads, pins and value. Last changed and by whom per part and per copy (git commit, Altium 365 revision, file date plus the web-app action), history of added / changed / removed copies in `<workspace>/hub/history.jsonl`, a part page with footprint pictures, pinout sketch, sources, release check, sign-off, where-used (`[hub] projects`), lifecycle and history, and fix buttons (make the KiCad version, Altium 365 dry run, build a library-only part with ecadlib). `hub.register_tool()` lets other tools' readers fill their columns. New `[hub]` rules section. The page opens on a tile per tool (parts, libraries, last change and by whom, what it lacks) that shows your library as it is in that tool, next to Compare all. Parts copy between Altium and KiCad (`POST /api/hub/copy`, librarian; `ecadlib hub --copy-to`; MCP `library_hub_copy`) into `<workspace>/hub/library`, and into a KiCad or Altium project from `[hub] projects` (its lib tables or .PrjPcb), with a Project filter using KiCad and Altium where-used.
- Web UI, more fluid and human-friendly: first-visit welcome with *Try it with a sample BOM* (`POST /api/demo`) and the setup check; drop a BOM anywhere; live per-part progress lines and a Stop button for long jobs (`POST /api/job/cancel`); parts as cards with a footprint picture and chips (status, cross-check, KiCad / Altium, cost and model); a side panel per part with the held reason and next step in plain words (`ecadlib/messages.py`), both values of a disagreement and the datasheet page; Undo for approve / reject / release anyway; search, filters, keyboard shortcuts (`?`); skip link, labels, contrast checked in both themes, reduced motion. `ecadlib/partview.py`, Workspace `library_parts` / `demo_bom`, `GET /api/parts`, MCP `library_parts`.
- The terminal, human-friendly (`ecadlib/term.py`): one status vocabulary (✓ ready, ! held, ○ waiting for sign-off), colour and symbols only on a terminal (never with `NO_COLOR`, `--json` or in CI), tables that fit the width, a summary block with what was written and the next commands, a live progress line for `librarian`, "waiting on X (12 s)" for slow network sources and model calls, and `-q` / `-v` on every command; used by `demo`, `init`, `doctor`, `librarian`, `triage`, `release-check`, `status`, `kicad-export`, `dblib-sync`, `altium-pkg`, `parity`, `eval gate`, `migrate`, `rebuild`, `agent status`, `queue list`. New `ecadlib review`: held parts one at a time with the reason in plain words; pick a candidate, release anyway or open the datasheet (never asks with `--yes` or when piped). `--json` output is unchanged; `ecadlib agent status` prints a summary and takes `--json` for the old JSON.
- One voice for everything people read (`docs/ui-voice.md`, `ecadlib/messages.py`): every held reason (release check, footprint check, KiCad/Altium match, cross-check, datasheet reader, standard parts, sign-off, library agent) has a code, a plain sentence and a next step (`messages.held(code, **values)`, `messages.explain(raw_reason)`); plans and `--json` keep their machine strings. Reports rewritten outcome first, grouped by what to do: `review.md` plus a new `review.html` (web UI look, light/dark), `release_check.md`, datasheet `*.review.md`, parity, eval `report.md`, test pack `CHECKLIST.md`, agent PR body and notifications, `ecadlib doctor`, Altium menu and KiCad plugin dialogs, init questions, MCP errors. Workspace `librarian_run` rows gain `word`/`says`, `held_parts` gains `reasons`; kicad-export `skipped` entries gain `says`. Tests: `tests/test_messages.py` (a new reason without a sentence fails), `tests/test_ui_voice.py` (snapshots, no internal names or absolute paths).
- Footprint rule book (`docs/footprint-rulebook.md`, `ecadlib/footprint_rules.py`): what a footprint must contain and look like, drawn from KLC F1-F9, KiCad's official library, IPC-7351 naming, Altium's IPC wizard layer conventions and Bogatin's public guidance. New rules `name` (KLC and IPC-7351 names checked against pin count, EP / MP count, pitch, body, chip codes, BGA grid and pad), `meta`, `attr`, `origin`, `layers`, `padshape`, `tht`, `vias`, `text`, `model`, `margin`, `polarity`, `graphics`, `connect`, `pinmap` (reversed diode / LED / polarized capacitor) and `silktext` (silkscreen text 0.5-2.0 mm, not over pads, the designator not over the body; also on the `.Designator` the Altium export writes and on the PcbLib read back, after the first real Altium run showed `.Designator` over an EasyEDA part), plus `check_pcblib` for the Altium side. `ecadlib check` runs the whole book (`--summary` for a library, `--geometry-only` for the old checks); the release check holds ecadlib's own and converted parts for `name`, `layers`, `attr`, `tht`, `vias` and `silktext` errors and every part for `pinmap`. Calibrated on 4,976 official KiCad footprints (errors on 0.5 %, all read); 24 of them are golden test fixtures.

- `ecadlib eval gate` (`ecadlib/eval/gate.py`): CI accuracy gate (own job `accuracy-gate`): the 331-case eval set offline with standard parts and a committed synthetic replay pack (`eval/replay/kicad-v1.json.gz`), checked against `eval/baselines/kicad-v1.json` (327/331); fails when a family drops more than 1 % or a passing case breaks; about 20 s. `ecadlib eval golden` (`ecadlib/eval/golden.py`): normalised fingerprints of the KiCad and Altium files for the testpack, the demo and 96 package specs (`eval/golden/*.txt`, no uuids, GUIDs or dates), checked by `tests/test_evalgate.py`; `--update` regenerates them for one reviewed commit.
- Updates never break a library: every file ecadlib writes and reads back has a schema version and a migration registry (`ecadlib/migrate.py`); older files are migrated (on disk only after a backup in `.ecadlib_backup/`), files from a newer ecadlib are refused with one "made by ecadlib X.Y; upgrade ecadlib" line. `ecadlib migrate [--check] [--dry-run]`, a doctor line, Workspace `file_formats`, MCP `file_formats`. `librarian_state.json` is now v2 (footprint name + geometry hash). Proved with sample workspaces made by v0.2.0, v0.3.0 and two later commits (`tests/fixtures/upgrade/`). The librarian writes `library.lock.json` (per part: fetched inputs with hashes, datasheet PDF / model / prompt version, ecadlib version, rules hash, output hashes); `ecadlib rebuild --check` rebuilds offline and reports drift (Workspace `rebuild_check`, MCP `rebuild_check`).

- Datasheet cross-checks (`crosscheck.py`): every footprint read from a datasheet is checked against the standard package table or an independent second read of only the critical numbers (reversed pages, cached, costed in `cost.jsonl`). A disagreement holds the part with both values in the review. Rules `[datasheet] cross_check = "auto"|"always"|"off"` (default `auto`) and `cross_check_model`. `[ai] temperature = "auto"` sends temperature 0 and a seed only to models that accept it, so default Claude requests are unchanged. Eval `--repeat` / `consistency` metric. Workspace + MCP `cross_checks`. Offline tests only.
- `ecadlib altium-menu` (`altium_menu.py`): an "ecadlib" menu inside Altium Designer, a DelphiScript script project with Add part from MPN, Check this project BOM and Open review queue; each entry runs `ecadlib altium-menu run-job` hidden through a request.ini / result.ini exchange, reinstalls the DbLib (or points at Altium 365), and an optional `.DXPPrf` adds the menu. Workspace `altium_menu` and MCP tool of the same name. The .pas is checked offline against a cited API allow-list; never run inside Altium.
- `ecadlib parity` (`parity.py`): reads back the KiCad and the Altium library of every part and compares pads, drills, paste / mask, exposed pad, courtyard, 3D model, pins, pin-to-pad mapping, key fields and the `.kicad_dbl` vs DbLib rows, with explicit tolerances; the release check (librarian, agent) holds a mismatched part with a per-field diff (`[release] parity = "hold" | "warn" | "off"`); `parity survey` covers every generator and standard-table footprint; run by `testpack` and `demo`; Workspace `parity` and MCP tool.
- `ecadlib kicad-pcm` (`kicad_pcm.py`): the library as a KiCad Plugin and Content Manager package (zip for "Install from File...", optional `repository.json`/`packages.json` with `--base-url`), metadata checked against KiCad's PCM schema; symbols point at `PCM_<lib>`, 3D models at `${KICADn_3RD_PARTY}`; `--kicad 7` writes KiCad 7 files; `--plugin` packages a pcbnew action plugin "ecadlib: add part". `ecadlib altium-pkg` (`altium_pkg.py`): Altium hand-off folder with a `.LibPkg` (compile to IntLib), a DelphiScript install project and a relative DbLib. Workspace `tool_packages` and MCP tool of the same name. Installed and checked in real KiCad 7.0.11; not run in Altium.

### Fixed

- Altium projects (`altium_project.py`, the menu's Check this project BOM / Fill): `[DeviceSheetN]` sheets are read (next to the project, as written, or in Altium's device-sheet and data folders / `$ECADLIB_DEVICE_SHEETS`) and one that cannot be found is a warning, not a silent skip (Altium's Bluetooth Sentinel example lost 10 sheets, 45 components); multi-channel sheets (`REPEAT(CH,1,4)`, or one file under several sheet symbols; the name is RECORD=32, the old check read 33) are listed once per channel with Altium's channel designators (`ChannelDesignatorFormatString`, default `$Component_$RoomName`); a component without an MPN parameter whose Comment reads as a part number uses the Comment (Content Vault parts), with a warning and a triage note.
- Found in Altium AD26 with NE555DR (EasyEDA C7593): EasyEDA footprints put REF** on silk above the courtyard and the value on fab below it (1 mm, 0.15 mm stroke; before both sat at the centre, so Altium drew ".Designator" across the pads), a `${REFERENCE}` goes on fab in the body (0.5-1.0 mm), and a pin-1 dot inside the body is moved beside pad 1, 0.2 mm clear of the pads; the result passes `footprint_rules` text / silktext. `texts_from_kicad` keeps a Fab-layer reference on Mechanical 13 (only a silk reference becomes Top Overlay).
- Altium vault item ids (`CMP-1035-02800-1`, the LibRef / Comment / Part Number of Content Vault and Altium 365 parts) are never used as an MPN: not from parameters, the Comment, ActiveBOM or the triage's LibRef fallback (`altium_project.is_vault_id`).
- JLCPCB answering 403 (or 429) is reported as "JLCPCB refused the request (403)"; nothing more is sent to JLCPCB in that run (no retries) and the other sources are still tried.
- Repeat channels whose sheet symbols share one name (Bluetooth Sentinel: six "Red_LED") get numbered rooms (Red_LED1 ... Red_LED6), so designators are unique.
- A held part that another ecadlib version or build (`librarian.BUILD_REV`, stamped in the state) or other rules built is built again on the next run; it was skipped, so the release check judged the old version's models and fields ("silk 0.000 mm", "Description empty" after upgrading). Ready parts are still kept untouched (`--refresh` rebuilds them).
- Standard chip resistors / capacitors (0201 ... 2512) and SOT-23 / SOD-123 / SOD-323 / SOT-323 get a package default 3D height when nothing better is known; the release check warns "HEIGHT from package default ..., verify" instead of holding the part.
- `ecadlib doctor --altium-menu X.ini` checks the ini's `workspace=` (relative to the ini's folder) unless `--workspace` is given.
- Report CSVs (triage, review, release check, project BOM, where-used, sourcing, lifecycle, dedupe, upstream) are written as UTF-8 with a BOM so Excel shows ± and µ; ecadlib's own readers (pandas, `read_bom`) already accept it.
- `ecadlib altium-menu` (found on a Windows PC with Altium AD26, ecadlib in a venv, no API key): `build` writes `command="<sys.executable>" -m ecadlib` on Windows when no `--command` is given and fills an empty `command=` of an existing `ecadlib_menu.ini` (before, the runner looked only on PATH / `py -3` / `python` and a venv install failed with "ecadlib was not found"); the script's and `altium-pkg`'s `IsInstalled` / `UninstallAll` loop over `InstalledLibraryCount`, the count `InstalledLibraryPath` indexes (was `AvailableLibraryCount`). `ecadlib doctor` checks the menu's `command=` (`--altium-menu`, or an `ecadlib_menu.ini` in the current folder / `out/altium_menu`) and gives `setx` / PowerShell hints for environment variables on Windows.
- EasyEDA footprints: silk lines are cut back to 0.2 mm from the pads and a silk circle within 0.1 mm of a pad is left out (EasyEDA outlines can run up to or over the copper; converted chip passives were held for "silkscreen is 0.000 mm from pad 1"). The part search's own description (JLCPCB `describe`, EasyEDA `description`, else its category + package) fills an empty Description.
- KiCad library index: tree pages are fetched with a 20 s timeout; a build that stops (timeout, HTTP 429) is not retried for 15 min (1 h after a 429), so runs in between go straight to the other sources, and resumes from the cached pages afterwards (`--refresh-index` retries at once).
- `dblib-sync` / `altium-pkg` on Windows: the Excel connection's `Data Source` is the library folder's real absolute path, also replacing the `C:\ecadlib\library` placeholder older versions wrote; a connection edited in Altium is kept.
- `footprint_check`: an F.Cu lead and a B.Cu heat spreader under thermal vias no longer count as overlapping copper.

- Cross-check: a pad-table (custom) read counts a numbered exposed pad as a pin (package_schema), the standard table does not; such reads of EP packages (WSON, LFCSP, TQFN, MSOP-EP) were held as "pin count 13 vs 12". The eval gate's replay pack now also answers the second read.
- `sexpr.courtyard_bbox` ignored `fp_arc` / `fp_circle` courtyards: round cans (TO-18, TO-46) got a 2 x 2 mm box off to one side, also in the eval set's references (3 rebuilt; `tht-LM134H`, `tht-SFH216` now pass the gate). `footprint_adv`: pad names `H…` / `S…` were mounting / shield pads (outside a detected JEDEC grid), so audio-jack sleeve contacts, rotary-encoder switch pins S1/S2 and H/S ball rows lost their pins; only `MP`, `SH` (KiCad's names) and `MH`/`MTG`/`MOUNT`/`MECH`/`NPTH` are non-pins now.
- KiCad library import (librarian) and `kicad-export`, found by `parity survey` over KiCad's own footprint library: a through-hole pad's drill offset is kept (Altium hole-offset field; before, the copper sat on the hole), an SMD pad's shape offset moves its copper, copper-less mask / paste apertures keep their round or custom shape and both their layers (before: a square on paste only), and `kicad-export` folds a custom pad's regions that touch the anchor, and the mask / paste of stroked outlines, back into the pad without swallowing separate paste polygons.
- `kicad-export`: footprints without a KiCad 3D model (all generated and standard ones) now get the Altium footprint's model (its embedded STEP, or its extruded body as a STEP) in `<lib>.3dshapes/`; before, the KiCad library had no 3D model where Altium had one.
- `ecadlib dblib`: the Excel `.DbLib` names its workbook relative to itself (`DatabasePathRelative=1`), so the folder can move.
- Web UI: a step bar (1. Check a BOM, 2. Fill the library, 3. Send to Altium, Review queue, Footprints, Status, Settings), a "what happened, what next" line after every action, a Status card (`GET /api/status`) and an in-page setup check (`GET /api/doctor`, admin in team mode), the librarian's progress in its own card, a note telling team viewers which role they need, and `tests/test_ui_browser.py` (Chromium via Playwright at desktop and phone width; skips without it).

### Fixed

- Web UI: a BOM that can't be read now gives one plain line (no `ValueError`, no server path, and the error is scrolled into view); "Check again" is disabled with a reason when there is no BOM; the queue's filter chips work from the keyboard; white-on-light-blue buttons in dark mode; no `/favicon.ico` 404; the triage result opens next to the BOM instead of below the review queue; a queue approval the plan refuses no longer says "approvals.py refused".
- Found by the new end-to-end tests (`tests/test_e2e.py`): a KiCad library part whose 3D model could not be downloaded (offline, blocked host) lost its official footprint (the librarian fell back to another source); the model is now just made here. `kicad-export` replaced the whole `fp-lib-table` / `sym-lib-table` (a second library, a project's own rows or the database row were dropped); it now adds or replaces only its own row, in place. `ecadlib init` crashed printing a numeric proposal (`symbols.pin_length`). Re-running the librarian rewrote an unchanged `.PcbLib` with a new date and `release-check --allow` left `plan.json` in a key order the next run changed: a second run now changes no library file. `.PcbLib` / `.SchLib` are written atomically.
- Librarian: two BOM lines with the same footprint name no longer share one footprint file unless the pads are the same (`ecadlib/fp_share.py`); a different land pattern gets its own name (the real package name, else `<name>_<part>`), carried into `footprint.ref`, the `.PcbLib`, the symbol's footprint link, `resolve`, the KiCad export and the agent. Parts an older run shared by name only are re-resolved; files parts already have keep their names. Eval over the `kicad` source: 20 wrong shared footprints -> 0. `eval run` gives chip passives and diodes R/C/L/D designators (chips were unresolved by every source). `stdparts`: pin-removed variants (`SOIC-8-N7`, `SOIC-14-16`) are no longer resolved as the full package.
- `standard` source never guesses: an IC family name without a body size (`SOIC-8`, `SO-14`, `TSSOP-14`, `LQFP-100`; `MSOP-8` excepted, JEDEC has one), a QFN/DFN or `-1EP` name without the exposed-pad size, and `TO-252-2` / `TO-263-2` / DPAK / D2PAK without a library prefix (KiCad also has `_TabPin1`) now return nothing, so the next source (datasheet) answers; TVS diodes get the footprint only (uni- or bidirectional pin names are not certain from the MPN). Eval, `standard` alone: 115 answers with 14 wrong -> 74 answers, 0 wrong.

- Datasheet route / stdparts / eval review (rvK): `[datasheet] max_attempts` no longer ends a ladder on a cheaper model (the last try allowed goes to the top model); a synchronous refusal / max_tokens answer is costed from its usage block (was a 6,000-token estimate); a missing API key no longer logs phantom costs and caches every step as failed (the next run used to start on the top model); a stale failed step at the end of a route no longer pays in a loop; the eval reports every paid answer of a part's route (and replays it), prices Haiku 5.5's >100K-token tier, and fails two pin names swapped between pins; stdparts gives nothing for tantalum / polymer / electrolytic capacitors (was a chip-capacitor land and an unpolarized symbol).
- Library agent batch PRs: when a part's new build has fewer files than its last one (a part removed from its BOM before a requested rebuild: nothing built, no AFTER pictures), its old pictures now leave the batch branch, and its other old files stay recorded in `batch.json`; before, they were forgotten and stayed in the open PR even after the part was rejected (rare soak-test failure).
- Inputs / exports / Altium review (rvJ): unannotated `R?` symbols in a `.kicad_sch` are counted one by one (two were one part); `kicad-dblib` merges tables and columns that differ only in case (SQLite crashed) and, on Windows, rewrites a database KiCad has open in one transaction; `export-parts --format xlsx` drops control characters openpyxl refused; the KiCad database library and parts export read and write UTF-8 on every locale; SchLib text gets Altium's `%UTF8%` twin for every non-ASCII value (`±`, `°`, `µ` too, as Altium writes it); on Windows the plan lock waits past msvcrt's 10-second limit and atomic writes retry while another process holds the file open.
- Hooks review: GitLab API calls and webhook posts no longer follow HTTP redirects (urllib resent `PRIVATE-TOKEN` / `Authorization` to whatever host a 30x named); a GitLab origin on a self-hosted host with `[agent] gitlab_api` left at gitlab.com is refused instead of sending that host's token to gitlab.com; a provider plugin whose constructor or `configured()` raises, or one in `[providers] order` that fails to load, no longer stops triage; `[notify]` skips the remaining posts once its time budget is used up.
- Plan rewrites wait for the library agent: `release-check`, `resolve choose` and `dedupe --merge` on an agent plan wait for `agent/plan.lock`, and the web UI / MCP release check, choose and merge refuse while the agent rebuilds (locked methods call unlocked internals, so choose and merge re-check without deadlocking), so an `--allow` is no longer dropped by the agent's save. `dedupe --merge` keeps the first `plan.json.pre-dedupe` and timestamps later backups. `approve status` names a policy from `[release.approvals]`. `count_refs` reads `R1 - R4` and counts `U1A, U1B` once.
- Core pipeline review: text files are UTF-8 on every platform (a `10kΩ` BOM value crashed the triage report on Windows, and a `µ` written as cp1252 could not be read back); plan and state files are written atomically, so a crash no longer leaves a truncated `plan.json`; `resolve choose` re-checks every part that shares the model file it overwrites (they stayed `ready`); prices like `0,125 €` are 0.125, not 125; RKM names `1F5` / `1m5` instead of `15` / `1M5`; `dedupe --bom` remaps the BOM sheet, not a cover sheet; lifecycle reads a DbLib in a folder named with `#`; concurrent HTTP cache writers no longer share one temp file, and a damaged cache entry is a miss.
- Checked against real KiCad 7.0.11 (`tests/test_kicad_real.py`, skips without KiCad; optional CI job `kicad`): `kicad_import` failed on footprint text `(at x y unlocked)` (48 of 2291 KiCad 7 library footprints sampled) and on zero-length arcs; KiCad 7 symbols lost their `ki_description`; an EasyEDA pin with a slanted path made KiCad reject the whole symbol library; an SMD-defined BGA land could leave 0.02 mm copper gaps without an error; density C put REF** on the silk outline; `footprint-bench` crashed on a drill offset. `test_kicad_export`'s kicad-cli check now knows KiCad 7 cannot open the KiCad 8 export.
- Spreadsheet formula injection: every report and export CSV (triage, sourcing, release check, librarian review, dedupe and its BOM copy, where-used, project BOM, lifecycle, upstream, the agent's library BOM) writes cells starting with `= + - @`, tab or CR with a leading apostrophe (`ecadlib/sheetsafe.py`); plain numbers such as `-5` stay, the DbLib keeps Altium's `=Value` literal, and BOMs read back unchanged. Excel number cells read as typed (`1e-07` F becomes `100n`, `1.0` becomes `1`), so part names never show exponents. UTF-16 BOMs without a byte-order mark are detected and read.
- Team server security review: the sign-in lockout could be beaten with parallel requests (now counted before the password check), **Change password** checked the current password with no lockout, a removed user's sessions came back when the name was added again, `TEAM_USERS.JSON` (case-insensitive disks) or a hard link served the password hashes, team files could be triaged as a BOM, sign-in accepted 20 MB JSON bodies, the Docker stack believed a `proxy_user_header` from `team.json` that Caddy passed on from any client, and the audit line was written after the response (a flaky test).
- Datasheet batches: a create whose answer was lost (timeout, 5xx) leaves a marker; the next run lists recent batches and adopts the matching one instead of paying twice, and refuses to resubmit an unconfirmed one without `--yes`. `output_config.effort` is only sent to models that accept it (stepping down to a supported level), 200K-context models get the 100-page PDF limit, worst-case estimates include a fallback re-run, responses are shape-checked by hand when jsonschema is missing, and a part's spec and symbol JSON never overwrite each other.
- Datasheet reader and visual proof (review): `[datasheet] max_cost_usd` now holds on every path (the librarian's synchronous calls, the single-part CLI with new `--rules`/`--yes`, cumulatively across parts) and refuses a model with no known price; collecting an already-submitted batch is never blocked by the cap. A visual proof no longer says "pass" when the model marked every check not_applicable (pad_count / pin_count / pin_numbers must match). Staggered pin headers report their real pitch and alternating numbering. Password-protected or damaged PDFs give a clear error instead of a crash when cut to pages, and a page the model cites outside the pages sent is flagged instead of shown as an original page number.
- Team server hardening: one deadline per request (a client trickling bytes held a thread forever), a cap on connections per address, listen backlog 128 (60 simultaneous sign-ins got connection resets), `team_audit.jsonl` rotation with tail-only reading, and per-address rate limiting of unauthenticated refusals in the audit log.

  arcs, keep-outs, extruded and embedded-STEP 3D bodies, multi-part symbols, hidden pins,

- Datasheet reader (`datasheet`): Claude reads a PDF and fills the package spec and the symbol.
- Lifecycle watcher (`lifecycle`): checks part status with Nexar, DigiKey and Mouser and can write the

  DFN families; IPC-7351B numbers taken from the tables KiCad builds its library with.
